# Tofu Infra Template

Scaffolds an OpenTofu root-module project with a Smith manifest. One template
covers the three major cloud providers — the choice is made at scaffold time
and baked into the project:

- **aws** — `hashicorp/aws` provider (default tags: project, environment,
  managed-by), `s3` state backend
- **gcp** — `hashicorp/google` provider (project + region), `gcs` state
  backend, namespaced per environment via `prefix`
- **azure** — `hashicorp/azurerm` provider, `azurerm` state backend
  (resource group + storage account)

`cloud_provider` drives `versions.tf` (provider block + version constraint),
`backend.tf` (empty backend block of the matching type), `main.tf` /
`outputs.tf` (a read-only identity data source + output that verifies
authentication on the first plan), the variables (`region`, `cloud_project`,
`environment`), and the README's auth/bootstrap instructions. Backend
*settings* are never hardcoded: backend blocks cannot reference variables, so
`hooks/post_gen_project.py` generates one `<env>.tfvars` +
`<env>.backend.tfvars` pair per comma-separated `environments` entry, with
backend fields matching the selected provider.

Variation lives inside the template, not in the template path taxonomy:
`smith new tofu/infra` is always the command, and cookiecutter choices (plus
the hook) do the branching.

```shell
smith new tofu/infra --version 1
```

```
tofu/infra/v1
├── cookiecutter.json
├── hooks/post_gen_project.py
└── {{cookiecutter.project_slug}}/
    ├── versions.tf            (provider block + pin, conditional on cloud_provider)
    ├── backend.tf             (s3 | gcs | azurerm empty backend block)
    ├── main.tf                (read-only identity data source, per provider)
    ├── outputs.tf             (identity output, per provider)
    ├── variables.tf           (region, cloud_project, environment)
    ├── environments/          (generated by the hook: <env>.tfvars + <env>.backend.tfvars)
    ├── smith.yml              (placeholder type — bind it by hand)
    └── README.md
```
